# 商人・預言者・指導者・ゴリラ — ルールと仕様（案 v0.1）

ジャレド・ダイアモンド『商人・預言者・指導者・王 リーダーは本当に歴史を動かすのか』
（土方奈美 訳、日経BP、2026年10月刊）をもとにした、2〜5人用のトリックテイキング。

シリーズの題の付け方をそのまま使う。

| 原題 | ゲーム | 差し替えた語 |
| --- | --- | --- |
| 第三のチンパンジー | 第三のゴリラ | チンパンジー → ゴリラ |
| 銃・病原菌・鉄 | 銃・病原菌・ダイヤモンド | 鉄 → ダイヤモンド |
| 商人・預言者・指導者・王 | **商人・預言者・指導者・ゴリラ** | 王 → ゴリラ |

リポジトリ名の案は `merchant-prophet-leader-gorilla`。王は役割として残るが、
題では王の座にゴリラが座る。本の問い「リーダーは本当に歴史を動かすのか」への
このゲームなりの答えは、**リーダーは自分の関心（スート）しか動かせず、
ゴリラ（成り行き）は何でも持っていく**、というもの。

---

## 1. 札（全40枚）

4スート × 1〜10。各（スート, 数字）の札は1枚ずつ。
スートは4つの役割に1つずつ対応する。

| スート | 印 | 対応する役割 |
| --- | --- | --- |
| 貨幣 | 🪙 | 商人 |
| 聖典 | 📜 | 預言者 |
| 旗 | 🚩 | 指導者 |
| 冠 | 👑 | 王 |

**ゴリラには対応するスートがない。** 切り札もない。

## 2. 役割と円卓

- 役割は **商人・預言者・指導者・王・ゴリラ** の5つ
- 卓の中央に5つの席をもつ **円卓** がある。プレイヤーは席0から時計回りに着き、
  5人未満なら残りは **空席** になる
- 役割の札は円卓の各席に1枚ずつ置かれ、**1トリックごとに円卓が1つ回って、
  役割が時計回りに隣の席へ移る**
- 1局は **5トリック**。円卓がちょうど1周するので、
  **人数にかかわらず、全員が5つの役割（ゴリラを含む）をそれぞれ1回だけ担う**
  （2〜4人のときは、空席にあるあいだの役割は担わない。
  つまり5人未満だと、担わない役割が1局に 5−人数 個ある）
- 空席にある役割のスートは、そのトリックでは **だれのものでもない**
- 役割の予定はすべて公開。誰がいつ何になるかは、局の最初から全員に見えている

### 例：5人・第1局

プレイヤー p のトリック t（0始まり）での役割は `役割[(p − t + 局オフセット) mod 5]`
（役割の並び: 0商人 1預言者 2指導者 3王 4ゴリラ、第1局のオフセットは0）。

| | T1 | T2 | T3 | T4 | T5 |
| --- | --- | --- | --- | --- | --- |
| P1 | 商人 | **ゴリラ** | 王 | 指導者 | 預言者 |
| P2 | 預言者 | 商人 | **ゴリラ** | 王 | 指導者 |
| P3 | 指導者 | 預言者 | 商人 | **ゴリラ** | 王 |
| P4 | 王 | 指導者 | 預言者 | 商人 | **ゴリラ** |
| P5 | **ゴリラ** | 王 | 指導者 | 預言者 | 商人 |

### 例：3人・第1局（P4・P5の席は空席）

| | T1 | T2 | T3 | T4 | T5 |
| --- | --- | --- | --- | --- | --- |
| P1 | 商人 | **ゴリラ** | 王 | 指導者 | 預言者 |
| P2 | 預言者 | 商人 | **ゴリラ** | 王 | 指導者 |
| P3 | 指導者 | 預言者 | 商人 | **ゴリラ** | 王 |
| 空席 | 王・ゴリラ | 指導者・王 | 預言者・指導者 | 商人・預言者 | 商人・ゴリラ |

T1とT5はゴリラが空席にいるので、そのトリックにゴリラはいない。

## 3. 準備（1局ごと）

1. 40枚をシャッフルし、各プレイヤーに **8枚** ずつ配る
2. 残りの札は伏せたまま使わない（5人なら残りは0枚）
3. 局オフセットに従って円卓に役割を置く

**8枚配って5枚しか出さない。** 手に残る3枚は局の終わりに捨てる（点にも失点にもならない）。
先の役割の予定が見えているので、「T4で王になるから冠の10は取っておく」のように、
どの札をどのトリックで使うかの計画がこのゲームの中心になる。

## 4. トリック

- 第1トリックのリードはその局の **親**。以降は前のトリックの勝者がリードする
- 親は第1局がP1、以降は局ごとに時計回りに移る
- **マストフォロー**：リードされたスートを持っていれば必ず出す。なければ何を出してもよい
- **リードされたスートでいちばん大きい数字** を出した人がトリックを取る（同じ札はないので同点はない）

## 5. 得点（トリックを取ったとき）

トリックを取った人は、**そのトリックでの自分の役割** に応じて得点する。

| 役割 | 得点 |
| --- | --- |
| 商人・預言者・指導者・王 | トリックの中の **自分のスートの札の数字の合計** |
| ゴリラ | トリックの中の札 **1枚につき3点**（スートは関係ない） |

- 自分のスートの札がないトリックを取っても0点
- トリックを取らなかった人は、自分のスートの札がそのトリックにあっても0点。
  **だれかが取ったトリックにある、取った人の役割以外のスートの札は、そのまま消える**
- ゴリラは空席のスートも、ほかのプレイヤーのスートも区別なく持っていく

### ゴリラの点を「1枚3点」にした理由

最初は「ゴリラは取った札の数字をすべて足す」を考えたが、簡易シミュレーション
（`tools/sim_balance.py`、各2万局）では、ゴリラの点が全得点の5〜6割を占め、
**ゴリラのトリックを取れたかどうかでほぼ勝負が決まる**ゲームになった。

| 人数 | 数字の合計 | 1枚2点 | **1枚3点** |
| --- | --- | --- | --- |
| 2人 | 42% | 19% | **25%** |
| 3人 | 51% | 27% | **35%** |
| 4人 | 57% | 32% | **41%** |
| 5人 | 61% | 36% | **46%** |

（表の値は全得点に占めるゴリラの点の割合。ゴリラがトリックを取る率は、人数に応じて64%〜29%）

「1枚3点」だと、ゴリラは1トリックで最大15点（5人）。スートの役割も、自分のスートの
高い札が2〜3枚集まれば同じくらいになる。ゴリラのトリックが局の山場になりつつ、
それ以外の4トリックもきちんと意味を持つ。
数字の合計を使うやり方は **変種「野生のゴリラ」** として設定で選べるようにする。

## 6. 局と決着

- 1局 = 5トリック。**局数は人数と同じ**（全員が1回ずつ親になる）。ただし2人は4局
- 局オフセットは局ごとに1ずつ増やす（ゴリラになる順番が局ごとに変わる）
- 全局の合計点がいちばん多い人の勝ち。同点は引き分け

## 7. 曖昧になりやすい点

- 「ターン」は1トリックのこと。役割は **トリックごと** に移る（局ごとではない）
- 役割は取ったトリックの **その時点の** 役割で数える。
  T2で商人だった人がT2のトリックを取れば、貨幣の札だけを数える
- 1局の中でゴリラになるのは1人1回だけ（円卓が1周で終わるので必ずそうなる）。
  2〜4人では、ゴリラが空席にいてだれもゴリラでないトリックがある
- リードする人は自分のスートを出す必要はない
- 手に残る3枚は公開しない

## 8. 数値まとめ

| 項目 | 値 |
| --- | --- |
| 人数 | 2〜5人 |
| 総札数 | 40（4スート × 1〜10） |
| 配る枚数 | 各8枚 |
| 1局のトリック数 | 5（役割の円卓がちょうど1周） |
| 手に残って捨てる札 | 各3枚 |
| 役割 | 5（商人・預言者・指導者・王・ゴリラ） |
| スートの役割の得点 | 取ったトリックの自分のスートの数字の合計 |
| ゴリラの得点 | 取ったトリックの札1枚につき3点（変種：数字の合計） |
| 局数 | 人数と同じ（2人は4局） |

## 9. アプリの仕様

作りは `guns-germs-and-diamond/CLAUDE.md` のツール群共通の規約と、
`gorilla-gorilla-gorilla` にそろえる。

### 9-1. 構成

    index.html                  紹介ページ（hero → specs → goods → about → howto → make → faq → cta → family → footer）
    app/index.html              ゲーム本体。HTML/CSS/JSを1ファイルに（ビルドなし・外部依存なし）
    assets/site.css             共通デザイン。アクセント色だけ変える（案：王の紫 #6b4a9e）
    assets/icon.png / favicon.png
    assets/goods.json           本の画像と価格（fetch_goods.py＋毎日3:00 JSTのワークフロー）
    img/1.png〜9.png            役割5枚＋スートの印4枚＝3x3グリッド1枚から切り分ける
    img/PROMPT.md               そのグリッドのプロンプト
    tools/split_grid.py         gorilla-gorilla-gorilla のものを流用
    tools/sim_balance.py        バランス確認用のシミュレーション
    RULES.md                    上の第1〜8節（実装の挙動と一致させる）
    sitemap.xml                 紹介ページと app/ の2本

- 本の棚には本書を載せる。ASIN は Amazon の商品ページで見えた `4296118587` だが、
  規約どおり Creators API の `searchItems` で実在を確かめてから載せる。
  既刊2作（第三のチンパンジー、銃・病原菌・鉄）も並べてシリーズとしてつなぐ
- GA4（`G-3FCFQY4W85`）は紹介ページだけ。JSON-LD・canonical・OG も規約どおり
- ゲーム画面にはクレジットや紹介文を出さない

### 9-2. 対戦

- **あなた＋CPU 1〜4人**（開始時に人数を選ぶ。既定は5人）
- CPUは all-in-texas の `PERSONAS` と同じ5人（ビエホ／ディアブロ／ゴルド／ヴィニー／ロコ）から
  人数ぶん選ぶ。`tight` / `aggr` / `bluff` の読み替えは次のとおり

| 値 | このゲームでの意味 |
| --- | --- |
| `tight` | 先の役割のために札を取っておく度合い（計画性） |
| `aggr` | ゴリラのトリックを取りに行く・止めに行く強さ |
| `bluff` | 自分のスートでないスートをリードして場を揺さぶる頻度 |

- むずかしさ：やさしい（CPUのぶれが大きい。出せる札のうち得になるものに印を出す）／
  ふつう／むずかしい（出た札を覚え、残りの高い札を読む）

### 9-3. CPUの思考（シミュレーションで使ったものを土台にする）

各候補札について次の和が最大のものを出す。

- **取り分** — その札で勝つなら、今の役割で得る点
- **妨害** — 今勝っている人の得点を消せるなら、その点の一部（ゴリラが勝ちそうなときは強く止める）
- **温存** — 先のトリックで自分のスートになる札・ゴリラの番で勝つための高い札を出すことの損
- **献上** — 負けるときに、勝つ人の得点になる札（その人のスート、ゴリラなら何でも）を出す損

むずかしさと人物の値で、各項の重みと乱数の幅を変える。

### 9-4. 画面

- 緑のラシャの卓。中央に **円卓**（5つの席と役割の札）。トリックのたびに円卓が回る演出
- 画面の上か横に **役割表**（プレイヤー × 5トリック）を常に出し、今のトリックの列を強調する。
  このゲームでいちばん大事な情報なので、スマートフォンでも省かない
- 各プレイヤーの席に、今の役割のアイコンと「このトリックで点になる札」（スートの印、ゴリラなら全部）を出す
- 取ったトリックの点は、その札の上に数字で出す
- ノートPC（1000×760）とスマートフォン（390×780）で縦スクロールなし
- 札の絵がなくても印と数字だけで遊べる（絵は読み込めたときだけ使う）

## 10. 決めたいこと（確認待ち）

1. **ゴリラの点**：標準を「1枚3点」、変種を「数字の合計」にしたが、逆でもよいか
2. **8枚配って5枚出す**：手に3枚残る。全部出させたいなら「5枚配る」にもできるが、
   先の役割に備えて札を選ぶ楽しさが減る
3. **局数**：人数と同じ（2人は4局）。固定の点数（例：100点先取）にしてもよい
4. **役割ごとの特殊能力**：いまはない（違いは点になるスートだけ）。
   例：王はそのトリックのリードを奪える、預言者は次のトリックの役割を1つ先に見られる、など。
   まずは能力なしで作り、遊んでから足すのがよいと考えている
5. **リポジトリ名**：`merchant-prophet-leader-gorilla` でよいか
